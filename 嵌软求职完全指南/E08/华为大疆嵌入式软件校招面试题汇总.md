# 一、华为（HUAWEI）嵌入式软件

## 1.1 面试流程（典型"一日三面"）

1. **笔试**：牛客考试系统，**3 道编程题**，有运气成分。常见题型：进制转换、超大数运算、图的遍历、字符串处理（如敏感字符打码、二进制码流等分）。华为对 **C 语言底层机制**（预编译、指针）考察是重中之重。
2. **一面（技术）**：开局**手撕代码**（如双指针）→ 深挖简历项目（从项目里学到了什么）→ 可能问 AI 相关 → 复盘笔试题及优化方向。
3. **二面（技术）**：手撕代码常为 **LeetCode "字符串解码"变体**；嵌入式岗手撕常"**四选一**"：**手写 PID / 最长公共子字符串 / 稀疏矩阵乘法 / 第 k 大的数**；之后八股 + 实习内容。
4. **主管面（综合素质）**：学习能力、抗压能力、团队协作、职业规划，基本不深挖技术。

## 1.2 华为高频考点清单

**C 语言 / 底层：** 指针与函数指针、预编译/宏、`volatile`/`const`/`static`、内存分区、字节序、结构体对齐。
**操作系统：** ⭐MMU（虚拟地址→物理地址转换）、分段/分页/分块、页面置换算法、裸机中断处理、进程/线程、用户态与内核态。
**计算机网络：** ⭐TCP/IP/UDP、TCP 三次握手四次挥手、多线程、网络编程。
**数据结构与算法：** 手撕题为主（双指针、字符串、矩阵、排序/查找、PID）。
**项目：** 项目是否从零构建、软硬件分工、遇到的困难与解决、队友分工。

## 1.3 华为重点题目 + 标准答案

### Q1. ⭐MMU 是什么？如何完成虚拟地址到物理地址的转换？
**答：** MMU（Memory Management Unit，内存管理单元）是 CPU 与物理内存之间的硬件部件，负责**虚拟地址（VA）→ 物理地址（PA）**的翻译、内存保护与缓存控制。
- 转换流程：CPU 发出虚拟地址 → MMU 先查 **TLB（快表）**，命中则直接得到物理页帧；未命中则查**页表**（多级页表），得到物理地址后回填 TLB。
- 同时做**权限检查**（读/写/执行、用户/内核），越权触发**缺页/保护异常**。
- 作用：让每个进程拥有**独立虚拟地址空间**（隔离、安全），并支持虚拟内存（换页）。

### Q2. ⭐TCP 三次握手与四次挥手？为什么挥手是四次？
**答：**
- **三次握手**：① Client 发 SYN(seq=x)；② Server 回 SYN+ACK(seq=y, ack=x+1)；③ Client 回 ACK(ack=y+1)。目的：双方确认收发能力，同步初始序列号。
- **四次挥手**：FIN→ACK→FIN→ACK。**握手三次而挥手四次**的原因：被动方收到 FIN 后，ACK 与自己的 FIN 不能合并——它可能还有数据没发完，所以先回 ACK，等数据发完再发 FIN，故拆成两步。
- **TIME_WAIT**（主动关闭方等 2MSL）：保证最后 ACK 到达，并让旧报文在网络中消散。

### Q3. ⭐TCP 与 UDP 的区别？分别用在哪里？
**答：** TCP 面向连接、可靠（确认/重传/排序）、有流量控制和拥塞控制、字节流、开销大；UDP 无连接、不可靠、无序、开销小、支持广播/多播。TCP 用于文件传输、网页（HTTP）；UDP 用于实时音视频、直播、DNS、物联网遥测。

### Q4. 进程与线程的区别？进程间通信（IPC）方式？
**答：**
- **区别**：进程是资源分配的基本单位（独立地址空间），线程是 CPU 调度的基本单位（共享所属进程的地址空间）。线程切换开销小、通信方便，但一个线程崩溃可能拖垮整个进程。
- **IPC 方式**：管道（匿名/命名）、消息队列、共享内存（最快，需配合信号量同步）、信号量、信号、Socket（可跨机器）。

### Q5. 页面置换算法有哪些？
**答：** FIFO（先进先出，可能有 Belady 异常）、LRU（最近最少使用，命中率高、实现成本高）、LFU（最不经常使用）、Clock/二次机会（LRU 的近似，工程常用）、OPT（最优，理论上界，不可实现）。

### Q6. 手撕 PID 算法（嵌入式岗常考）
**答：** 位置式增量式都要会。位置式：
```c
typedef struct { float Kp, Ki, Kd;
    float setpoint, integral, prev_err; } PID;

float PID_update(PID *p, float measure, float dt) {
    float err = p->setpoint - measure;
    p->integral += err * dt;                 // 积分项（注意限幅防积分饱和）
    float deriv = (err - p->prev_err) / dt;  // 微分项
    p->prev_err = err;
    return p->Kp*err + p->Ki*p->integral + p->Kd*deriv;
}
```
**加分点**：积分限幅（抗积分饱和 anti-windup）、微分先行、输出限幅。

### Q7. 第 k 大的数（手撕高频）
**答：** 最优用**快速选择（quickselect）**，平均 O(n)；或维护**大小为 k 的小顶堆**，O(n·logk)，适合数据流/海量数据。

# 二、大疆（DJI）嵌入式软件

## 2.1 面试流程

1. **测评**：线上选择题约 100 道，考性格、价值观、逻辑（所有岗位都有）。
2. **专业笔试**（线上）：题型丰富——单选、多选、判断、填空、简答、编程。
   - 2019 届 A 卷构成：**单选 10 + 多选 5 + 填空 4 + 问答 3 + 编程 2**。
   - 知识点：C 语言、汇编、操作系统、Linux、RTOS、ARM 内核计组。
3. **一面（技术，约 45–48 min）**：自我介绍 → 项目深挖 → Linux/单片机/C 基础八股。
4. **二面（技术 + 项目，约 45 min）**：项目技术细节、难点与解决、产品改进建议、Linux 虚拟文件系统等更深入话题。
5. **HR/主管面（约 30 min）**：工作意向、职业规划，不涉及技术。

## 2.2 大疆笔试题型还原（2019 A 卷）

- **单选/多选**：C 语言基础、Linux 进程线程、**I2C/SPI/USB 等通信协议对比**。
- **填空**：C 变量的存储区域、`volatile`/`extern` 等关键字（作用阶段）、Linux 设备文件、编译过程。
- **问答**：实时系统 vs 非实时系统的优缺点、`static` 关键字的意义、**无锁编程**。
- **编程**：① **环形缓冲区（RingBuf）写入接口实现**；② **两个有序数组合并**（归并）。

## 2.3 大疆高频考点清单

**C 语言：** 编译过程、内存分段、⭐函数指针 vs 指针函数、栈溢出判断、堆栈、`static`/`volatile`、结构体字节对齐、大小端、指针 vs 引用。
**RTOS：** ⭐线程状态及转换、任务调度与优先级、上下文切换（PendSV）、互斥锁 vs 信号量、⭐优先级反转及解决、无锁编程。
**硬件/架构：** MCU 选型、⭐有 cache 的 CPU 上 DMA 如何保证数据一致性、STM32 启动流程与中断处理、ARM 架构、⭐SPI 四种模式、I2C/UART 接收方式（轮询/中断/DMA）。
**Linux/驱动：** 内核组成、⭐虚拟文件系统（VFS）、用户态/内核态、管道原理、段错误定位、Bootloader 启动流程、字符设备驱动、`kmalloc` vs `vmalloc`、中断处理（上/下半部）。
**项目：** 每个项目的需求来源、实现思路、难点、技术与产品线对比、固件网络升级的安全性、按键消抖、系统卡死定位。

## 2.4 大疆重点题目 + 标准答案

### Q1. ⭐函数指针 与 指针函数 的区别？
**答：**
- **指针函数**：本质是**函数**，返回值是指针。`int* func(int);`
- **函数指针**：本质是**指针**，指向一个函数。`int (*p)(int);`
口诀：看 `*` 是否被括号绑定到名字上——`(*p)` 是指针，`*func` 是返回指针的函数。函数指针常用于**回调**、状态机跳转表。

### Q2. ⭐环形缓冲区（Ring Buffer）写入接口实现
**答：** 典型 4K 大小，读写指针循环复用。无锁单生产者-单消费者实现：
```c
typedef struct {
    uint8_t *buf;
    uint32_t size;        // 必须为 2 的幂，便于用 & 取模
    volatile uint32_t in; // 写指针
    volatile uint32_t out;// 读指针
} RingBuf;

uint32_t rb_write(RingBuf *r, const uint8_t *data, uint32_t len) {
    uint32_t free = r->size - (r->in - r->out); // 可写空间
    if (len > free) len = free;                  // 防覆盖
    for (uint32_t i = 0; i < len; i++)
        r->buf[(r->in + i) & (r->size - 1)] = data[i];
    r->in += len;        // 让 in/out 自然溢出回绕
    return len;          // 返回实际写入字节数
}
```
**考点**：① 满/空判断（用 `in-out` 之差，或留一个空位区分）；② `size` 取 2 的幂用位运算取模；③ 单生产单消费下读写指针分离可**免锁**；④ 多核需内存屏障。

### Q3. ⭐有 Cache 的 CPU 上，DMA 如何保证数据一致性？
**答：** 问题根源：DMA 直接读写**物理内存**，而 CPU 读写的是 **Cache**，二者可能不一致。
- **DMA 写内存（外设→内存，接收）**：传输完成后，要**使（invalidate）对应区域的 Cache 失效**，强制 CPU 重新从内存读最新数据。
- **CPU 写内存→DMA 发送（内存→外设）**：启动 DMA 前要把 **Cache 内容刷回（clean/flush）内存**，保证外设读到最新数据。
- 工程手段：① 用**非缓存（non-cacheable）内存**做 DMA buffer；② 手动 `cache clean/invalidate`；③ 注意 buffer 按 **cache line 对齐**，避免边界脏数据。

### Q4. ⭐线程/任务有哪些状态？如何转换？
**答（RTOS）：** 就绪（Ready）、运行（Running）、阻塞/挂起（Blocked，等信号量/延时/事件）、挂起（Suspended）、删除/休眠。
- Ready→Running：被调度器选中（最高优先级就绪任务）；
- Running→Ready：被更高优先级任务抢占或时间片用完；
- Running→Blocked：主动等待资源（`take` 信号量超时、`delay`）；
- Blocked→Ready：等待条件满足（拿到信号量/超时到）。

### Q5. ⭐优先级反转是什么？怎么解决？
**答：** 高优先级任务 H 等待低优先级任务 L 持有的互斥锁，而中优先级任务 M 此时抢占了 L，导致 H 被 M 间接阻塞——高优先级反而被"插队"。
**解决：** ① **优先级继承**（L 临时提升到 H 的优先级，用完恢复，FreeRTOS Mutex 默认支持）；② **优先级天花板**（持锁即提升到该资源的最高使用优先级）。

### Q6. ⭐SPI 的四种模式？
**答：** 由 **CPOL（时钟空闲电平）** 和 **CPHA（采样边沿）** 组合而成：
| Mode | CPOL | CPHA | 采样边沿 |
|---|---|---|---|
| 0 | 0 | 0 | 第一个边沿（上升沿）采样 |
| 1 | 0 | 1 | 第二个边沿（下降沿）采样 |
| 2 | 1 | 0 | 第一个边沿（下降沿）采样 |
| 3 | 1 | 1 | 第二个边沿（上升沿）采样 |
主从设备模式必须一致才能正常通信。

### Q7. 实时系统 vs 非实时系统的优缺点？
**答：** 实时系统强调**确定性**（任务在限定时间内完成，可预测），分硬实时（错过即失败，如飞控/刹车）和软实时（偶尔超时可容忍，如视频）；优点是响应及时、可靠，缺点是吞吐量/资源利用率往往低于分时系统。非实时（通用 OS）追求平均吞吐和公平，响应时间不保证。

### Q8. 段错误（Segmentation Fault）如何定位？
**答：** 常见原因：野指针/空指针解引用、数组越界、栈溢出、写只读内存。定位手段：① `gdb` 运行 + `bt` 看调用栈；② core dump（`ulimit -c unlimited` 后 `gdb 程序 core`）；③ `addr2line` 由地址定位代码行；④ AddressSanitizer（`-fsanitize=address`）；⑤ 嵌入式裸机看 HardFault 入栈的 LR/PC。

# 三、两家共同必背"八股"速查（⭐核心）

| 主题 | 一句话要点 |
|---|---|
| `volatile` | 禁止编译器优化，每次从内存重读；用于寄存器/ISR 共享变量/多线程标志。≠原子≠线程安全 |
| `const` | 只读保护；`const靠谁近谁不可改` |
| `static` | 局部→延长生命周期；全局/函数→限制作用域为本文件 |
| 内存分区 | 栈/堆/数据段(.data/.bss)/常量区(.rodata)/代码段(.text) |
| 堆 vs 栈 | 栈自动分配向低地址、堆手动分配向高地址；栈快堆灵活 |
| 大小端 | 小端低位在低地址(x86/多数ARM)；union 或指针强转可判断 |
| `sizeof` vs `strlen` | sizeof 编译期含'\0'；strlen 运行期不含'\0' |
| I2C/SPI/UART | 见下方对比 |
| DMA | 不占 CPU 直接搬数据，完成中断通知；注意 cache 一致性 |
| 中断 | ISR 要短：只采样/搬运/置位/通知，复杂处理交任务 |

**三大通信协议对比：**
| | UART | SPI | I2C |
|---|---|---|---|
| 同步 | 异步 | 同步 | 同步 |
| 线 | 2(TX/RX) | 4(MOSI/MISO/SCLK/CS) | 2(SDA/SCL) |
| 双工 | 全双工 | 全双工 | 半双工 |
| 速度 | 低 | 高 | 中 |
| 寻址 | 点对点 | 片选 CS | 7 位地址 |

# 四、备考与分享建议

1. **C 语言底层是命脉**：两家都把 C 当"硬通货"，尤其华为考预编译/指针、大疆考存储区域/对齐/函数指针。务必能**手写**而非只会背。
2. **手撕代码必练**：华为（PID/字符串/矩阵/第k大）、大疆（环形缓冲区/归并）——这些都要能白板默写。
3. **项目要能深挖三层**："做了什么 → 为什么这么做 → 遇到什么坑怎么解决"，大疆尤其爱追问真实性。
4. **大疆偏底层**（内核/驱动/RTOS/cache/DMA），**华为偏计算机基础**（OS/网络/数据结构）+ 综合素质抗压，按目标公司侧重准备。
5. 分享选题可拆成系列：①C语言八股篇 ②RTOS/操作系统篇 ③通信协议与外设篇 ④手撕代码篇 ⑤项目如何讲。
