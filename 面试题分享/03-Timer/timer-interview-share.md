# 定时器 PWM 和定时中断嵌入式面试分享题库

> 适用场景：嵌入式软件、MCU 驱动开发、电机控制、数字电源、DC-DC 变换器、逆变器、工业控制方向面试分享。
>
> 说明：日常说的“定时器”不只是延时和周期中断。真正面试里经常会问到 PWM 输出、输入捕获、输出比较、编码器模式、主从同步、ADC 触发、互补 PWM、死区、刹车保护和控制环定时调度。

建议从一个常见问题切入：

## 3. 第一等级：基础知识详细答案

### 3.1 MCU 定时器本质上是什么？

定时器本质上是一个硬件计数器。

它由某个时钟源驱动，每来一个计数时钟，计数器 `CNT` 按配置向上、向下或上下计数。

常见用途：

- 周期中断。
- 延时和时间戳。
- PWM 输出。
- 输出比较。
- 输入捕获。
- 编码器接口。
- ADC/DAC 触发。
- 多定时器同步。

面试回答：

> 定时器不是软件 delay，而是由硬件时钟驱动的计数器。它可以在计数溢出、比较匹配、输入边沿捕获等事件发生时产生中断、DMA 请求、输出翻转，或者触发 ADC 采样。

### 3.2 PSC、ARR、CNT、CCR 分别是什么？

常见寄存器：

| 名称 | 含义 |
| --- | --- |
| `PSC` | Prescaler，预分频器，把定时器输入时钟降频 |
| `ARR` | Auto Reload Register，自动重装载值，决定计数周期 |
| `CNT` | Counter，当前计数值 |
| `CCR` | Capture/Compare Register，捕获/比较寄存器，用于 PWM 占空比、输出比较或输入捕获 |

直观理解：

```text
定时器输入时钟
    ↓
PSC 分频
    ↓
CNT 计数
    ↓
CNT 到 ARR 产生 Update event
    ↓
CNT 和 CCR 匹配产生 Compare event
```

面试回答：

> PSC 决定计数器多久加一次，ARR 决定一个周期数多少下，CNT 是当前计数值，CCR 是比较值。做定时中断时主要看 PSC 和 ARR；做 PWM 时 ARR 决定周期，CCR 决定占空比。

### 3.3 定时器中断周期怎么计算？

向上计数模式下：

```text
f_cnt = f_tim / (PSC + 1)
f_update = f_tim / ((PSC + 1) * (ARR + 1))
T_update = 1 / f_update
```

例如定时器时钟 `72 MHz`，想要 `1 ms` 中断：

```text
PSC = 7199
ARR = 9

f_cnt = 72 MHz / (7199 + 1) = 10 kHz
f_update = 10 kHz / (9 + 1) = 1 kHz
T = 1 ms
```

面试加分点：

> 很多 MCU 的定时器时钟不一定等于 APB 总线时钟。以 STM32 为例，某些系列里 APB prescaler 不为 1 时，定时器时钟可能是 APB 时钟的 2 倍，所以计算前要先确认 timer clock。

### 3.4 PWM 频率和占空比怎么计算？

边沿对齐、向上计数 PWM：

```text
f_pwm = f_tim / ((PSC + 1) * (ARR + 1))
duty ≈ CCR / (ARR + 1)
```

例如：

```text
f_tim = 72 MHz
PSC = 0
ARR = 3599

f_pwm = 72 MHz / 3600 = 20 kHz
```

如果想要 30% 占空比：

```text
CCR ≈ 3600 * 0.3 = 1080
```

注意：

- 不同 PWM 模式和极性下，高电平对应关系可能相反。
- 有些库里设置 `Pulse = CCR`。
- `CCR = 0` 和 `CCR >= ARR` 的边界行为要看具体定时器实现和 PWM mode。

### 3.5 Update event 是什么？

Update event 通常在以下情况产生：

- 计数器溢出或下溢。
- 计数器重新初始化。
- 软件强制产生更新。
- 某些主从触发导致重新装载。

它常用于：

- 触发周期中断。
- 把 preload 寄存器里的值更新到真正生效的影子寄存器。
- 触发 ADC/DAC。
- 作为主定时器同步其他外设。

面试回答：

> Update event 可以理解成定时器一个周期结束或重新装载的事件。它不只是中断来源，还经常作为 PWM 参数同步更新和外设触发的时间点。

### 3.6 Output Compare 和 PWM 有什么关系？

Output Compare 是“当 `CNT == CCR` 时做一个动作”。

这个动作可以是：

- 输出翻转。
- 输出置高。
- 输出置低。
- 产生中断。
- 产生 DMA 请求。

PWM 可以理解为 Output Compare 的一种典型应用：

```text
CNT 从 0 计到 ARR
CNT < CCR 时输出一种电平
CNT >= CCR 时输出另一种电平
```

所以：

- `ARR` 决定周期。
- `CCR` 决定边沿位置。
- 输出模式和极性决定高低电平关系。

### 3.7 Input Capture 是什么？

Input Capture 是定时器检测到输入边沿时，把当前 `CNT` 锁存到 `CCR`。

常见用途：

- 测频率。
- 测周期。
- 测脉宽。
- 测 PWM 占空比。
- 测霍尔传感器边沿间隔。

测频率例子：

```text
第一次上升沿捕获 CNT1
第二次上升沿捕获 CNT2
delta = CNT2 - CNT1
period = delta / f_cnt
frequency = 1 / period
```

面试加分点：

> 输入捕获要处理计数器回绕。如果 CNT 从最大值回到 0，中间差值不能简单相减，还要按计数器周期补偿。

### 3.8 边沿对齐 PWM 和中心对齐 PWM 有什么区别？

边沿对齐：

```text
CNT: 0 -> ARR -> 0
```

特点：

- 实现简单。
- 频率计算直接。
- 开关边沿集中在周期的一侧。

中心对齐：

```text
CNT: 0 -> ARR -> 0
```

但计数是先上数再下数。

特点：

- PWM 波形围绕周期中心对称。
- 常用于电机控制和功率变换器。
- 谐波和 EMI 特性更好。
- 更方便在 PWM 中点触发 ADC 电流采样。

中心对齐常见频率关系：

```text
f_pwm = f_tim / (2 * (PSC + 1) * (ARR + 1))
```

具体是否乘 2，要看芯片手册对 center-aligned 模式的定义。

### 3.9 基本、通用、高级定时器有什么区别？

常见分类：

| 类型 | 常见能力 | 适用场景 |
| --- | --- | --- |
| 基本定时器 | 计数、Update 中断、触发 DAC/ADC | 周期任务、时间基准 |
| 通用定时器 | PWM、输入捕获、输出比较、编码器模式 | 普通 PWM、测频、编码器 |
| 高级定时器 | 互补 PWM、死区、Break、重复计数器 | 电机控制、逆变器、DC-DC |

面试回答：

> 如果只是做 1ms 周期中断，用基本定时器就够了；如果要做 PWM、输入捕获、编码器，就需要通用定时器；如果要驱动半桥、三相桥，通常要用高级定时器，因为它支持互补输出、死区和 Break 保护。

### 3.10 定时器中断和软件 delay 有什么区别？

软件 delay：

- 占用 CPU。
- 精度受编译优化、中断和主频影响。
- 不适合实时任务调度。

定时器中断：

- 由硬件计数触发。
- CPU 可以做其他事情。
- 周期更稳定。
- 适合周期任务、控制环、超时检测。

面试回答：

> 软件 delay 是 CPU 空等，定时器中断是硬件到点通知 CPU。真正项目里周期采样、控制环、通信超时、PWM 更新一般都应该用定时器或硬件事件，而不是靠 delay。

## 4. 第二等级：驱动应用详细答案

### 4.1 怎么配置一个 1ms 的定时器任务中断？

步骤：

1. 确认定时器输入时钟 `f_tim`。
2. 选择 `PSC`，得到合适的计数频率。
3. 根据目标周期计算 `ARR`。
4. 开启 Update interrupt。
5. 在 ISR 里清标志位并执行短小任务。

例子：

```text
f_tim = 72 MHz
目标 = 1 ms

PSC = 7199 -> f_cnt = 10 kHz
ARR = 9    -> f_update = 1 kHz
```

ISR 里适合做：

- 置标志位。
- 简单计数。
- 读取少量状态。
- 触发控制环。

ISR 里不适合做：

- `printf`。
- `delay`。
- 阻塞等待。
- 大量浮点计算。
- 文件/Flash 擦写。
- 复杂协议解析。

### 4.2 定时器任务中断有什么实时性问题？

关键点：

- 中断优先级。
- ISR 执行时间。
- 中断嵌套。
- 临界区关中断。
- RTOS 调度延迟。
- 共享变量同步。

常见问题：

- ISR 太长导致低优先级中断丢失。
- 控制环周期抖动。
- 多个定时器中断互相抢占。
- 在 ISR 里调用不可重入函数。
- 中断里直接跑业务逻辑，后期越来越难维护。

面试回答：

> 定时器中断适合做硬实时触发，但 ISR 应尽量短。一般在中断里只做采样、控制计算或置事件标志，复杂业务交给任务处理。电机电流环这种硬实时逻辑可以放在高优先级定时中断或 ADC 回调里，但日志和通信解析不应该放进去。

### 4.3 PWM 频率和分辨率有什么矛盾？

PWM 频率：

```text
f_pwm = f_tim / ((PSC + 1) * (ARR + 1))
```

占空比分辨率主要由 `ARR + 1` 决定。

如果 `f_tim` 固定：

- PWM 频率越高，`ARR` 越小。
- `ARR` 越小，占空比可调档位越少。
- 分辨率越低，控制越粗。

例子：

```text
f_tim = 72 MHz
PWM = 20 kHz, PSC = 0
ARR = 3599
约 3600 档，占空比分辨率约 0.028%

PWM = 200 kHz, PSC = 0
ARR = 359
约 360 档，占空比分辨率约 0.278%
```

面试回答：

> PWM 频率不是越高越好。频率高可以减小电感电流纹波和噪声，但在定时器时钟固定时会降低占空比分辨率，还会增加开关损耗。电机和 DC-DC 里要在开关损耗、纹波、噪声和控制分辨率之间折中。

### 4.4 修改 CCR 为什么可能导致 PWM 毛刺？

如果没有使用 preload/影子寄存器，软件在一个 PWM 周期中间直接修改 `CCR`，可能导致：

- 本周期出现异常窄脉冲。
- 本周期占空比突然跳变。
- 多相 PWM 更新不同步。
- 三相桥某一相先变，另外两相后变。

更稳妥的方式：

- 开启 CCR preload。
- 在周期中写 preload 寄存器。
- 等 Update event 时统一生效。

面试回答：

> PWM 占空比最好在 update event 同步更新。尤其是三相电机或全桥变换器，多个 CCR 要一起更新，否则某个通道提前生效，可能导致电流畸变甚至功率级异常。

### 4.5 PWM Mode 1、Mode 2 和极性怎么理解？

常见 PWM mode：

- PWM Mode 1：在一种计数关系下输出有效电平。
- PWM Mode 2：和 Mode 1 相反。

再叠加输出极性：

- Active high。
- Active low。

所以不能只看 `CCR`，还要看：

- PWM mode。
- 输出极性。
- 互补输出极性。
- 死区后实际输出。
- 驱动芯片输入有效电平。

面试回答：

> 占空比不是只看 CCR，还要看 PWM mode 和极性。工程上一定要用示波器确认 MCU 引脚和驱动芯片输入端实际波形，特别是互补 PWM 和低有效驱动场景。

### 4.6 为什么电机控制常用中心对齐 PWM？

中心对齐 PWM 常见优点：

- 开关边沿对称，谐波特性更好。
- 相比边沿对齐，电流纹波分布更均匀。
- 更容易在 PWM 周期中心采样电流。
- 三相 PWM 更新更容易同步。

电机控制里常见做法：

```text
高级定时器输出三相中心对齐 PWM
    ↓
在 PWM 中点触发 ADC 采样相电流
    ↓
ADC 转换完成后运行 FOC 电流环
    ↓
计算新的三相占空比
    ↓
下一个 update event 同步更新 CCR
```

### 4.7 定时器如何触发 ADC 采样？

常见方式：

- Timer Update event 触发 ADC。
- Timer Compare event 触发 ADC。
- Timer TRGO/TRGO2 作为 ADC external trigger。
- PWM 某个隐藏通道专门用来产生 ADC 采样点。

为什么不用软件在中断里启动 ADC？

- 软件触发有中断延迟。
- 抖动更大。
- 采样点不稳定。
- 在电机/电源控制中容易采到开关噪声。

面试回答：

> 电机相电流或电源电感电流最好用 PWM 定时器硬件触发 ADC，而不是软件随机采样。这样采样点和 PWM 波形有固定相位关系，可以避开开关瞬间，提高采样一致性。

### 4.8 定时器 DMA 有什么用？

定时器可以在特定事件发生时发 DMA 请求。

常见用途：

- DMA 更新 CCR，生成任意 PWM 占空比序列。
- DMA 更新 ARR，实现变频输出。
- DMA 读取输入捕获结果，减少中断频率。
- DMA 批量更新多个定时器寄存器。
- LED 灯带、步进电机脉冲序列、波形发生器。

面试回答：

> 定时器 DMA 的价值是把周期性、重复性的寄存器更新交给硬件搬运，减少 CPU 干预和中断抖动。比如每个 PWM 周期自动更新 CCR，就可以生成精确的占空比序列。

### 4.9 输入捕获如何测 PWM 的频率和占空比？

一种常见方法：

- 通道 1 捕获上升沿，用于测周期。
- 通道 2 捕获下降沿，用于测高电平宽度。
- 或使用 PWM input mode，把两个捕获通道组合起来。

计算：

```text
period_count = rising2 - rising1
high_count = falling - rising1

frequency = f_cnt / period_count
duty = high_count / period_count
```

注意：

- 要处理 CNT 回绕。
- 要处理输入滤波。
- 要处理超时无信号。
- 高频信号需要足够高的计数时钟。
- 低频信号可能需要更大的 ARR 或 32 位定时器。

### 4.10 编码器模式怎么工作？

增量式编码器常见 A/B 两相信号，相位差 90 度。

定时器编码器模式可以：

- 根据 A/B 相边沿自动计数。
- 根据相位关系判断方向。
- 1x、2x、4x 计数。
- CPU 只需要周期读取 CNT。

常见面试点：

- 如何处理计数器回绕。
- 如何估算速度。
- 如何做输入滤波。
- 如何处理中断和 Z 相归零。
- 高速编码器计数频率是否超过定时器能力。

面试回答：

> 用定时器编码器模式可以把 AB 相解码交给硬件，不需要软件在 GPIO 中断里数边沿。软件周期读取 CNT，通过本次和上次计数差值算速度，并处理回绕和噪声滤波。

### 4.11 多个 PWM 通道如何同步更新？

典型场景：

- 三相逆变器。
- 全桥 DC-DC。
- 多相交错 Buck。
- 多路同步采样。

关键措施：

- 使用同一个高级定时器的多个通道。
- 开启 CCR preload。
- 在同一个 update event 同步生效。
- 多定时器时使用主从同步。
- 必要时使用 DMA burst 批量更新。

面试回答：

> 多路 PWM 不能让每个通道随写随生效。工程上一般让多个 CCR 先写入 preload，再在同一个 update event 同步更新，避免相位关系被破坏。

### 4.12 多个定时器之间怎么同步？

常见方式：

- Master timer 输出 TRGO。
- Slave timer 接收 ITR 触发。
- Reset mode：触发后从 0 重新计数。
- Gated mode：触发有效时才计数。
- Trigger mode：触发后启动计数。
- 外部触发输入 ETR。

适用场景：

- 多相 PWM 相位同步。
- PWM 和 ADC 同步。
- 捕获外部事件后启动定时窗口。
- 一个时间基准驱动多个任务。

## 5. 第三等级：项目实战详细答案

### 5.1 半桥/三相桥为什么需要互补 PWM？

半桥通常有高边管和低边管：

```text
Vbus
  |
 High-side MOSFET
  |
 Phase node
  |
 Low-side MOSFET
  |
 GND
```

互补 PWM 的意思是：

- 高边导通时，低边关闭。
- 低边导通时，高边关闭。
- 中间插入死区时间。

在三相电机、逆变器、同步 Buck、全桥变换器中，经常需要互补 PWM。

面试回答：

> 互补 PWM 用来驱动半桥上下管。它不是简单取反，因为上下管关断和导通都有延迟，中间必须插入死区，否则可能上下管同时导通，形成直通。

### 5.2 什么是死区时间？为什么没有死区会炸管？

死区时间是高边和低边切换时，两者都关闭的一小段时间。

原因：

- MOSFET/IGBT 不会瞬间关断。
- 驱动器有传播延迟。
- 栅极电荷释放需要时间。
- PCB 和器件存在寄生参数。

如果没有死区：

```text
高边还没完全关断
低边已经打开
    ↓
Vbus 直接短到 GND
    ↓
大电流直通
    ↓
功率管损坏
```

面试加分点：

> 死区太小会有直通风险，死区太大也不好，会增加波形畸变和有效占空比误差。电机控制里有时还需要做死区补偿。

### 5.3 Break/Trip 保护有什么用？

Break 或 Trip 是高级 PWM 外设里的硬件保护机制。

常见触发源：

- 过流比较器。
- 过压保护。
- 驱动芯片故障脚。
- 急停信号。
- 外部保护逻辑。

触发后可以：

- 立即关断 PWM。
- 强制输出安全电平。
- 进入高阻态。
- 产生故障中断。
- 锁存故障直到软件确认。

面试回答：

> 过流保护不能只靠软件中断，因为软件响应可能太慢。功率级保护通常要让比较器或驱动芯片直接进定时器 Break/Trip 输入，由硬件在很短时间内关断 PWM。

### 5.4 电机相电流为什么要同步到 PWM 中点采样？

PWM 开关瞬间会有：

- 电流快速变化。
- 开关尖峰。
- 地弹。
- ADC 采样噪声。
- 运放恢复时间。

如果随机采样，相电流会很抖。

更好的做法：

```text
PWM 定时器中心对齐计数
    ↓
在开关相对稳定的中点产生 ADC trigger
    ↓
ADC 采样相电流
    ↓
ADC 完成后运行电流环
```

面试回答：

> 电流采样点要和 PWM 波形同步，尽量避开开关边沿。FOC 里通常用高级定时器的 TRGO 或某个 compare event 触发 ADC，在 PWM 中点或有效采样窗口内采相电流。

### 5.5 FOC 电流环为什么通常用 10kHz 以上定时触发？

FOC 电流环控制对象是电机绕组电流。

电机电气时间常数：

```text
tau = L / R
```

控制环要足够快，才能在电流变化太大之前修正。

常见经验：

- PWM 频率：10kHz 到 30kHz 常见。
- 电流采样/电流环：通常和 PWM 同频或半频。
- 电流环带宽：明显低于采样频率，但要快于机械环。

面试回答：

> 电机控制里速度环可以慢一些，但电流环必须快。常见做法是用 PWM 定时器或 ADC 完成中断触发 FOC 电流环，保证采样、计算和 PWM 更新都有固定时序。

### 5.6 SVPWM 对定时器有什么要求？

SVPWM 最终也要落到三相占空比：

```text
duty_a
duty_b
duty_c
```

对定时器要求：

- 三相 PWM 同一个周期。
- 三相 CCR 同步更新。
- 通常用中心对齐。
- 需要互补输出和死区。
- 需要和 ADC 采样同步。
- 需要处理最小脉宽和采样窗口。

面试回答：

> SVPWM 算法输出的是三相占空比，真正落地靠高级定时器生成三相互补 PWM。难点不只是算 duty，还包括同步更新、死区、ADC 触发和保护输入。

### 5.7 DC-DC 变换器里定时器怎么参与闭环控制？

以 Buck 为例：

```text
PWM 控制 MOSFET
    ↓
电感电流和输出电压变化
    ↓
ADC 在固定时刻采样电压/电流
    ↓
PI 控制器计算新的 duty
    ↓
下一个 PWM 周期更新 CCR
```

定时器参与：

- 产生固定频率 PWM。
- 控制采样时刻。
- 触发 ADC。
- 触发控制中断。
- 输出互补 PWM 和死区。
- 故障时通过 Break 关断。

面试回答：

> 数字电源里定时器是整个闭环的时间基准。PWM、ADC 采样和控制计算必须同步，否则采样相位漂移会影响环路稳定性。

### 5.8 高开关频率下为什么 PWM 分辨率会不够？

假设定时器时钟 `100 MHz`。

如果 PWM 频率是 `100 kHz`：

```text
ARR + 1 = 100 MHz / 100 kHz = 1000
```

占空比约 1000 档。

如果 PWM 频率是 `1 MHz`：

```text
ARR + 1 = 100 MHz / 1 MHz = 100
```

占空比只有约 100 档。

对于数字电源，高频开关可能带来：

- 占空比分辨率不足。
- 输出电压调节不细。
- 小信号控制量被量化。
- 需要更高频定时器或高分辨率 PWM。

### 5.9 电流环中断和 RTOS 任务应该怎么分工？

推荐思路：

```text
高优先级定时器/ADC 中断：
    采样电流
    跑电流环
    更新 PWM
    做快速保护

RTOS 任务：
    通信
    日志
    状态机
    慢速速度环/位置环
    参数更新
```

注意：

- 不要把硬实时电流环放到普通低优先级任务里。
- 控制 ISR 不要打印日志。
- 共享参数要双缓冲或临界区保护。
- 慢速任务不要阻塞控制中断。

面试回答：

> 电流环和 PWM 更新属于硬实时路径，应该由定时器或 ADC 事件稳定触发；通信、日志和上位机参数处理可以放 RTOS 任务。控制中断要短，任务层做慢速逻辑。

### 5.10 编码器速度估算有哪些坑？

常见问题：

- CNT 回绕。
- 低速时差分量化误差大。
- 高速时计数变化太快。
- 编码器噪声导致速度尖峰。
- A/B 相接反导致方向反。
- 输入滤波太强导致高速丢边沿。

常见做法：

- 周期读取 CNT，计算 delta。
- 根据 ARR/编码器 CPR 处理回绕。
- 对速度做移动平均或低通滤波。
- 对异常速度做限幅。
- 高速场景确认输入捕获滤波不会吞边沿。

### 5.11 多相交错变换器如何实现相位错开？

多相 Buck、PFC、LLC 控制中可能需要相位错开。

例如两相交错 Buck：

```text
Phase A: 0°
Phase B: 180°
```

实现方式：

- 主定时器作为同步源。
- 从定时器通过 trigger 启动。
- 设置不同初始 CNT 或 phase register。
- 使用同一个 PWM 模块里的相位控制功能。
- 所有相位的更新点要同步。

面试回答：

> 多相交错不是简单开多个 PWM，而是要保证相位关系稳定。通常用定时器同步和相位偏移功能，让各相 PWM 在同一个时间基准下运行。

### 5.12 如何定位 PWM 波形偶发异常？

排查层次：

1. 确认定时器时钟、PSC、ARR、CCR。
2. 用示波器看 PWM 频率、占空比、死区。
3. 检查 CCR 是否开启 preload。
4. 检查 Update event 是否按预期产生。
5. 检查 Break/MOE 是否导致输出被关断。
6. 检查中断是否超时、嵌套或被屏蔽。
7. 检查多通道是否同步更新。
8. 检查 ADC 触发点是否落在开关噪声区。
9. 检查功率驱动芯片是否进入保护。

面试回答：

> 定位 PWM 问题不能只看软件变量，要用示波器同时看 PWM、互补输出、死区、ADC 触发点和故障脚。很多偶发问题其实是更新时机、Break 输入或中断抖动导致的。

## 6. 常见计算题模板

### 6.1 72MHz 定时器生成 1ms 中断

```text
f_tim = 72 MHz
目标中断频率 = 1 kHz

选择 PSC = 7199
f_cnt = 72 MHz / 7200 = 10 kHz

选择 ARR = 9
f_update = 10 kHz / 10 = 1 kHz
T = 1 ms
```

### 6.2 72MHz 定时器生成 20kHz 边沿对齐 PWM

```text
f_tim = 72 MHz
PSC = 0
目标 PWM = 20 kHz

ARR + 1 = 72 MHz / 20 kHz = 3600
ARR = 3599
```

30% duty：

```text
CCR = 3600 * 0.3 = 1080
```

### 6.3 72MHz 定时器生成 20kHz 中心对齐 PWM

如果中心对齐频率按上下计数计算：

```text
f_pwm = f_tim / (2 * (PSC + 1) * (ARR + 1))

ARR + 1 = 72 MHz / (2 * 20 kHz) = 1800
ARR = 1799
```

### 6.4 100MHz 定时器下 200kHz PWM 的分辨率

```text
ARR + 1 = 100 MHz / 200 kHz = 500
```

占空比分辨率：

```text
1 / 500 = 0.2%
```

如果控制器希望 duty 变化精度优于 0.05%，这个频率和时钟组合就不够。
