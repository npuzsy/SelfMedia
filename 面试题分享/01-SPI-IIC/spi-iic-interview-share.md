## 3. I2C 详细答案

### 3.1 I2C 的基本信号是什么？

I2C 最基本的两根信号线：

- `SCL`：Serial Clock，串行时钟线，通常由主机产生。
- `SDA`：Serial Data，串行数据线，双向数据线。

两根线都通常采用开漏/开集输出，再通过上拉电阻拉到高电平。

面试回答：

> I2C 是两线同步串行总线，SCL 提供时钟，SDA 传输数据。它通过地址区分从设备，所以多个从设备可以挂在同一组 SDA/SCL 上。因为总线是开漏结构，设备只能主动拉低，释放后由上拉电阻拉高，因此可以实现多设备共享、ACK、仲裁等机制。

### 3.2 为什么 I2C 要上拉电阻？

I2C 设备通常不能主动输出高电平，只能：

- 输出低电平：把线拉到 GND。
- 输出高电平：释放总线，由外部上拉电阻拉高。

这样设计有几个好处：

- 多个设备同时接在总线上时，不会出现一个设备强推高、另一个设备强拉低导致短路。
- 可以实现“线与”逻辑：只要有任意设备拉低，总线就是低电平。
- 可以支持 ACK、多主机仲裁、clock stretching 等机制。

工程注意点：

- 上拉电阻太大：上升沿慢，波形变圆，速度上不去。
- 上拉电阻太小：低电平电流变大，设备可能拉不动，功耗增加。
- 总线电容越大，需要越小的上拉电阻才能满足上升时间，但又不能小到超过器件的灌电流能力。

### 3.3 START、STOP、Repeated START 是什么？

I2C 中，数据在 `SCL` 高电平期间应保持稳定，通常只在 `SCL` 低电平期间变化。但 START 和 STOP 是两个例外：

- START：`SCL` 为高时，`SDA` 从高变低。
- STOP：`SCL` 为高时，`SDA` 从低变高。
- Repeated START：没有先发 STOP，而是在一次事务中再次发送 START。

常见寄存器读取流程：

```text
START
发送设备地址 + Write
发送寄存器地址
Repeated START
发送设备地址 + Read
读取数据
NACK
STOP
```

为什么要 Repeated START？

> 因为很多 I2C 设备读取寄存器时，需要先写入寄存器地址，再切换为读。如果中间发 STOP，有些设备可能认为一次事务结束，内部地址指针或状态机会变化。Repeated START 可以在不释放总线的情况下切换方向。

### 3.4 ACK/NACK 是怎么来的？

I2C 每传输 8 bit 后，第 9 个时钟周期用于 ACK/NACK。

- 接收方拉低 SDA：ACK，表示收到。
- 接收方释放 SDA：NACK，表示未响应或不再继续。

注意谁接收谁 ACK：

- 主机写从机时，从机接收数据，所以从机 ACK。
- 主机读从机时，主机接收数据，所以主机 ACK。
- 主机读最后一个字节后通常发送 NACK，告诉从机“我不继续读了”，然后 STOP。

面试加分点：

> I2C 的 ACK 是字节级握手，不等于业务数据一定正确。实际产品里如果数据重要，仍然可能需要 CRC、校验和、重试、超时等机制。

### 3.5 7 位地址、8 位地址、10 位地址怎么理解？

常见 I2C 从设备地址是 7 位地址。实际发送地址阶段时，主机会发送 8 bit：

```text
bit7..bit1: 7 位设备地址
bit0: R/W 位，0 表示写，1 表示读
```

所以很多数据手册里会出现两种写法：

- 7 位地址：例如 `0x68`。
- 8 位写地址/读地址：例如写 `0xD0`，读 `0xD1`。

两者关系：

```text
8 位写地址 = 7 位地址 << 1 | 0
8 位读地址 = 7 位地址 << 1 | 1
```

面试时建议明确说：

> MCU HAL/SDK 需要的是 7 位地址还是左移后的 8 位地址，要看具体库接口。很多 I2C 调试错误都来自地址格式搞错。

10 位地址可以扩展地址空间，但工程中不如 7 位地址常见，而且主机、驱动和从设备都要支持。

### 3.6 I2C 常见速度有哪些？

常见模式：

| 模式 | 典型速率 |
| --- | --- |
| Standard-mode | 100 kbit/s |
| Fast-mode | 400 kbit/s |
| Fast-mode Plus | 1 Mbit/s |
| High-speed mode | 3.4 Mbit/s |
| Ultra Fast-mode | 5 Mbit/s，单向 |

面试回答不要只说“最高 3.4M”或“最高 5M”。更好的说法：

> I2C 有不同速度等级，但实际速度取决于主控、从设备、上拉电阻、总线电容、线长和波形质量。很多普通传感器只支持 100k 或 400k，不能只看 MCU 支持多快。

### 3.7 Clock stretching 是什么？

Clock stretching 是从机把 `SCL` 拉低，延迟主机继续产生时钟的一种机制。

典型场景：

- 从机内部还没准备好数据。
- 从机处理速度较慢。
- 从机需要等待内部 ADC 转换、存储器写入等操作。

面试回答：

> I2C 的 SCL 也是开漏结构，从机可以在需要等待时拉低 SCL，让主机看到 SCL 还没有真正变高，从而暂停传输。这个机制叫 clock stretching。但不是所有主机控制器或软件库都支持它，实际选型时要确认。

### 3.8 I2C 多主机仲裁怎么做？

I2C 支持多主机，但实际产品里用得不多。仲裁依赖开漏总线：

- 主机发送高电平时，本质是释放总线。
- 如果另一个主机发送低电平，总线实际为低。
- 某主机发现自己想发 1，但读回是 0，说明自己输了仲裁，应停止发送。

核心点：

> I2C 仲裁不会破坏总线上的数据，因为低电平占优，输掉仲裁的主机退出，赢的主机继续完成传输。

### 3.9 I2C 总线卡死怎么恢复？

常见现象：

- SDA 一直被拉低。
- SCL 一直被拉低。
- 主机发送 START/STOP 失败。
- 扫描不到设备。

可能原因：

- 主机在传输中复位，从机还停在等待后续时钟的状态。
- 从机异常，持续拉低 SDA 或 SCL。
- 上拉电阻不合适，波形达不到高电平。
- 地址冲突，多个设备同时响应。
- 线长、电容、干扰导致时序错误。

常见恢复策略：

1. 先把 I2C 外设关闭，把 SCL/SDA 配成 GPIO 开漏输入/输出。
2. 如果 SDA 被拉低，手动输出 9 个左右 SCL 脉冲，尝试让从机释放数据位。
3. 手动构造 STOP：SCL 高时让 SDA 从低到高。
4. 重新初始化 I2C 外设。
5. 如果仍失败，对异常从设备复位或断电重启。

面试加分点：

> 产品里最好给关键 I2C 设备留复位脚或电源开关，否则某个外设锁死时，MCU 只能软恢复，恢复不了就只能整机复位。

## 4. SPI 详细答案

### 4.1 SPI 的基本信号是什么？

常见 4 线 SPI：

- `SCLK`：串行时钟，由主机产生。
- `MOSI`：Master Out Slave In，主机发给从机。
- `MISO`：Master In Slave Out，从机发给主机。
- `CS`/`SS`/`NSS`：片选信号，通常低有效，由主机选择某个从机。

面试回答：

> SPI 是同步串行接口，通常由主机产生时钟和片选。MOSI 和 MISO 分开，所以标准 4 线 SPI 可以全双工通信。主机通过拉低某个从机的 CS 来选择通信对象。

### 4.2 SPI 为什么读数据也要发 dummy byte？

SPI 的本质是移位同步通信。每来一个 SCLK：

- 主机通过 MOSI 移出 1 bit。
- 从机通过 MISO 移出 1 bit。

所以主机想读从机数据时，也必须产生时钟。很多 MCU SPI 外设只有“发送时才产生时钟”，因此软件上会写一个无意义字节，例如 `0xFF` 或 `0x00`，用来换回 MISO 上的数据。

面试回答：

> SPI 没有单独的“只读时钟”概念，读也是通过主机发送 dummy 数据来提供 SCLK。从机在这些时钟边沿把数据移出，主机同步采样 MISO。

### 4.3 CPOL/CPHA 和 SPI Mode 怎么理解？

SPI 最容易被问到的时序题是 CPOL/CPHA：

- `CPOL`：Clock Polarity，时钟空闲电平。
  - CPOL = 0：空闲时 SCLK 为低。
  - CPOL = 1：空闲时 SCLK 为高。
- `CPHA`：Clock Phase，数据在哪个边沿采样。
  - CPHA = 0：第一个有效边沿采样。
  - CPHA = 1：第二个有效边沿采样。

常见模式：

| Mode | CPOL | CPHA | 直观理解 |
| --- | --- | --- | --- |
| Mode 0 | 0 | 0 | 空闲低，第一个边沿采样 |
| Mode 1 | 0 | 1 | 空闲低，第二个边沿采样 |
| Mode 2 | 1 | 0 | 空闲高，第一个边沿采样 |
| Mode 3 | 1 | 1 | 空闲高，第二个边沿采样 |

面试回答：

> SPI 没有像 I2C 那样统一严格的总线协议，不同器件可能要求不同 SPI mode。驱动时必须以从设备数据手册为准，配置 CPOL、CPHA、bit order、最大时钟频率、CS 建立/保持时间。

### 4.4 SPI 多从机怎么连接？

最常见方式：

```text
主机 SCLK  -> 所有从机 SCLK
主机 MOSI  -> 所有从机 MOSI
所有从机 MISO -> 主机 MISO
主机 CS0   -> 从机 0 CS
主机 CS1   -> 从机 1 CS
主机 CS2   -> 从机 2 CS
```

主机每次只拉低一个 CS，未选中的从机应该忽略 SCLK/MOSI，并让 MISO 进入高阻态。

工程风险：

- 如果多个 CS 同时有效，多个从机可能同时驱动 MISO，导致总线冲突。
- 有些从机的 MISO 在未选中时不是高阻，需要外加三态缓冲或单独隔离。
- 不同从机可能要求不同 SPI mode、不同最大时钟，切换 CS 前要切换 SPI 配置。

### 4.5 SPI 有没有 ACK？怎么保证可靠性？

标准 SPI 没有 I2C 那种字节级 ACK/NACK。主机发出去，从机是否理解、是否执行成功，取决于从设备协议。

常见可靠性手段：

- 读状态寄存器确认。
- 数据帧加 CRC/checksum。
- 命令加响应码。
- 超时重试。
- 使用 `DRDY`/`BUSY`/`READY` 引脚做硬件握手。
- 对 Flash/EEPROM 这类器件，写完后轮询 WIP/BUSY 位。

面试回答：

> SPI 协议本身简单高速，但可靠性机制通常要放到器件协议或驱动层实现，例如状态寄存器、CRC、重试和超时。

### 4.6 SPI daisy chain 是什么？

Daisy chain 是把多个 SPI 从机串成移位链：

```text
主机 MOSI -> 从机 A DIN
从机 A DOUT -> 从机 B DIN
从机 B DOUT -> 从机 C DIN
从机 C DOUT -> 主机 MISO
```

优点：

- 可以减少 CS 数量。
- 适合移位寄存器、LED 驱动、部分 DAC/ADC 等支持链式模式的器件。

缺点：

- 所有设备必须支持 daisy chain。
- 一次通信要移过整条链，延迟增加。
- 某个设备异常可能影响后面设备。
- 帧格式和位数管理更复杂。

面试回答：

> Daisy chain 不是所有 SPI 器件都能用，它要求器件协议支持级联移位。普通 SPI 多设备更常用独立 CS。

## 5. I2C 和 SPI 的异同

### 5.1 对比表

| 对比项 | I2C | SPI |
| --- | --- | --- |
| 线数 | 2 根：SDA、SCL | 常见 4 根：MOSI、MISO、SCLK、CS |
| 寻址方式 | 地址寻址 | 片选 CS |
| 通信方向 | 半双工 | 通常全双工 |
| 主从关系 | 支持多主，但常用单主 | 通常单主多从 |
| 速率 | 常见 100k/400k/1M/3.4M | 常见 MHz 到几十 MHz |
| 硬件成本 | 省 IO，但要上拉 | IO 多，连接简单 |
| 协议复杂度 | 有 START/STOP/ACK/仲裁等 | 协议简单，细节由器件定义 |
| 可靠性 | 有 ACK，但不代表数据业务正确 | 无标准 ACK，需要上层协议 |
| 多设备能力 | 地址足够且电气允许即可挂多个 | 多设备通常需要多个 CS |
| 典型应用 | 传感器、RTC、EEPROM、PMIC | Flash、SD 卡、屏幕、ADC/DAC、高速传感器 |

### 5.2 面试回答模板

> I2C 和 SPI 都是同步串行总线。I2C 用 SDA/SCL 两根线，通过设备地址访问从机，优点是省 IO、适合多个低速外设，缺点是速度较低、受上拉电阻和总线电容影响明显，也会遇到地址冲突。SPI 通常使用 MOSI/MISO/SCLK/CS，主机用 CS 选择从机，优点是速度高、全双工、时序简单，缺点是占用 IO 多，没有统一 ACK，多个设备需要更多片选线或额外扩展。选型时，如果是低速配置类、多设备、IO 紧张，倾向 I2C；如果是高速数据流、Flash、显示屏、ADC 等，倾向 SPI。

## 6. 常见应用场景

### 6.1 I2C 常见应用

- 温湿度、气压、光照、IMU 等低速传感器。
- RTC 实时时钟。
- EEPROM。
- PMIC、电源管理芯片。
- GPIO expander。
- 小尺寸 OLED。
- 电池管理、充电芯片。
- 板内多个配置寄存器型器件。

适合 I2C 的特征：

- 数据量不大。
- 设备数量较多。
- MCU IO 比较紧张。
- 通信距离较短，板内连接为主。
- 对实时吞吐要求不高。

### 6.2 SPI 常见应用

- NOR Flash、NAND Flash。
- SD 卡。
- TFT/LCD 显示屏。
- 高速 ADC/DAC。
- 以太网、Wi-Fi、LoRa、蓝牙等通信模块。
- 需要较高采样率的传感器。
- 移位寄存器、LED 驱动。

适合 SPI 的特征：

- 数据量较大。
- 对速率要求高。
- 能接受更多 IO。
- 通信对象数量不太多，或可以通过译码器扩展 CS。
- 需要简单、确定性较好的时序。

## 7. 拔高题 1：I2C 最多挂载多少个设备？为什么？怎么计算？

### 7.1 标准回答

不能简单回答“最多 127 个”或“最多 112 个”。I2C 最多挂多少设备要同时看两个限制：

1. 地址限制。
2. 电气限制，尤其是总线电容和上升时间。

地址层面：

- 7 位地址理论空间是 128 个。
- 其中 `0000xxx` 和 `1111xxx` 两组地址被规范保留用于特殊用途，所以常见说法是普通 7 位从设备最多约 112 个地址。
- 10 位地址可以扩展地址空间，但工程中不常用，需要主机、从机和驱动都支持。

电气层面：

- 每个器件引脚、PCB 走线、连接器、线缆都会增加 SDA/SCL 上的电容。
- 电容越大，上拉电阻把总线拉回高电平越慢。
- 上升时间过慢会导致高速下采样错误，或者不满足 I2C 时序规范。
- 标准/快速模式工程中常用的总线电容上限参考值是 400 pF，但具体还要结合速度等级和器件能力。

所以实际产品里，先到瓶颈的往往不是地址数量，而是电容、上拉、线长、带宽、驱动能力和软件复杂度。

### 7.2 总线电容怎么算？

估算公式：

```text
Cbus = Cmaster + ΣCslave + Cpcb + Ccable + Cconnector + Cmargin
```

其中：

- `Cmaster`：主控 I2C 引脚输入/输出电容。
- `ΣCslave`：所有从设备 SDA/SCL 引脚电容之和。
- `Cpcb`：PCB 走线寄生电容。
- `Ccable`：线缆电容，如果有外接线尤其重要。
- `Cconnector`：连接器、ESD、防护器件等引入的电容。
- `Cmargin`：设计余量。

最大设备数量估算：

```text
Nmax = floor((Cb_max - Cmaster - Cpcb - Ccable - Cconnector - Cmargin) / Cslave_per_device)
```

举例：

```text
假设：
Cb_max = 400 pF
Cmaster = 10 pF
Cpcb + Cconnector = 80 pF
Cmargin = 50 pF
每个从设备引脚电容约 10 pF

Nmax = floor((400 - 10 - 80 - 50) / 10)
     = floor(260 / 10)
     = 26
```

这只是电容角度的估算，还没有考虑：

- 地址是否冲突。
- 每个器件是否都支持目标速率。
- 上拉电阻是否还能满足上升时间。
- MCU 是否有足够的软件调度能力。
- 传输带宽是否足够。

### 7.3 上拉电阻怎么和电容一起算？

I2C 上升时间和上拉电阻、总线电容近似关系：

```text
tr ≈ 0.8473 * Rp * Cbus
```

所以：

```text
Rp(max) = tr(max) / (0.8473 * Cbus)
```

同时，低电平时设备要能把总线拉下来，所以：

```text
Rp(min) = (VDD - VOL(max)) / IOL
```

设计时要满足：

```text
Rp(min) <= Rp <= Rp(max)
```

如果发现 `Rp(min) > Rp(max)`，说明在当前电压、速度、总线电容和器件下拉能力下没有合适的上拉电阻。解决办法通常是：

- 降低 I2C 速率。
- 减少挂载设备数量。
- 缩短走线/线缆。
- 减小输入电容和 ESD 器件电容。
- 使用更强驱动能力的 Fast-mode Plus 器件。
- 使用 I2C buffer/repeater/mux 分段。

### 7.4 面试回答模板

> I2C 最多挂多少设备不能只看地址。7 位地址理论 128 个，但有保留地址，普通 7 位从设备常说约 112 个可用地址；10 位地址可以更多，但不常用。工程上更关键的是总线电容和上升时间。每个器件、走线、线缆都会增加 Cbus，Cbus 越大，上拉电阻拉高越慢。可以用 `Cbus = Cmaster + ΣCslave + Cpcb + Ccable + Cmargin` 估算，再结合 `tr ≈ 0.8473 * Rp * Cbus` 和下拉电流限制选择上拉电阻。实际超过限制时，要降速、分段、用 buffer 或 I2C 多路复用器。

## 8. 拔高题 2：SPI 一般是主机发起通信，如果从机想发起怎么做？

### 8.1 标准回答

标准 SPI 从机不能真正主动发起 SPI 通信，因为：

- 从机通常不能产生 SCLK。
- 从机不能主动拉低自己的 CS。
- 主机不提供时钟，从机数据就无法移出。

所以从机想“主动发起”，实际要变成“从机通知主机，由主机发起 SPI 读”。

典型方案是增加一根 GPIO 中断/握手线：

```text
从机数据准备好
    ↓
从机拉低/拉高 IRQ、DRDY、READY
    ↓
主机 GPIO 中断触发
    ↓
主机拉低 CS
    ↓
主机产生 SCLK
    ↓
主机发送读命令或 dummy byte
    ↓
主机从 MISO 读出数据
```

### 8.2 常见硬件信号命名

- `IRQ`：Interrupt Request，中断请求。
- `DRDY`：Data Ready，数据准备好。
- `READY`：从机准备好。
- `BUSY`：从机忙，主机等 BUSY 释放后再访问。
- `INT`：通用中断脚。

### 8.3 面试回答模板

> SPI 从机一般不能主动发起标准 SPI 事务，因为时钟和片选都由主机控制。如果从机有数据要上报，常见做法是额外加一根中断或 data-ready GPIO，从机拉这个脚通知主机，主机收到中断后再拉低 CS、产生 SCLK，把数据读走。也可以用主机轮询状态寄存器，但实时性和效率较差。

### 8.4 工程展开

方案对比：

| 方案 | 优点 | 缺点 |
| --- | --- | --- |
| 从机 IRQ/DRDY 通知主机 | 实时性好，常用 | 多占一根 GPIO |
| 主机周期轮询状态寄存器 | 硬件简单 | 延迟和总线占用较大 |
| READY/BUSY 握手 | 适合耗时操作 | 软件状态机更复杂 |
| 换成 UART/CAN/USB 等协议 | 从机可主动发数据 | 硬件和协议成本不同 |

实际驱动设计建议：

- 中断里只置标志，不要在中断里做大量 SPI 传输。
- 主循环或 RTOS 任务中处理 SPI 读。
- 读之前确认 READY/BUSY 状态。
- 给 SPI 事务加超时，防止从机异常导致主机卡死。
- 如果数据帧重要，加 CRC 或序号，避免漏帧或错帧无法发现。

## 9. 拔高题 3：模块地址没办法修改，怎么在一个总线上管理多个设备？

### 9.1 问题本质

如果多个 I2C 设备地址完全相同，并且同时接在同一条 I2C 总线上，主机无法区分它们。

例如两个传感器地址都是 `0x40`：

```text
主机发送地址 0x40
两个传感器同时 ACK
两个传感器可能同时驱动 SDA 返回数据
```

结果：

- 写操作时两个设备可能同时被配置。
- 读操作时两个设备可能同时输出数据，造成数据混乱。
- 如果两个设备输出位不同，SDA 会被低电平设备拉低，主机读到的数据不可控。

### 9.2 解决方案

#### 方案 1：I2C 多路复用器/开关

例如 TI TCA9548A 这类 8 通道 I2C switch/mux。

连接方式：

```text
MCU I2C
  ↓
I2C MUX
  ├── Channel 0: 设备 A，地址 0x40
  ├── Channel 1: 设备 B，地址 0x40
  ├── Channel 2: 设备 C，地址 0x40
  └── ...
```

访问流程：

```text
1. 主机访问 mux 自己的地址
2. 写控制寄存器，打开某个通道
3. 主机访问目标设备地址 0x40
4. 切换通道后，再访问另一个 0x40 设备
```

优点：

- 方案成熟，最常用。
- 可以解决地址冲突。
- 可以隔离总线电容，缓解挂载设备过多的问题。
- 某个下游分支异常时，有机会只隔离该分支。

缺点：

- 增加 BOM 和驱动逻辑。
- 同一时刻通常只访问选中的通道。
- 如果同时打开多个通道，地址冲突和电容叠加问题仍可能出现。

#### 方案 2：I2C 地址转换器

例如 LTC4316 这类 I2C/SMBus address translator。

思路：

```text
主机侧看到地址 0x41
地址转换器把它转换为设备真实地址 0x40
设备仍认为自己被 0x40 访问
```

优点：

- 可以让固定相同地址的设备在同一主总线上共存。
- 对下游设备透明。
- 某些器件用电阻配置新地址，不需要软件编程。

缺点：

- 成本更高。
- 地址映射要仔细设计，避免映射后仍冲突。
- 不是所有时序、速度、特殊命令都适合无脑套用，需要读数据手册。

#### 方案 3：使用多个 I2C 控制器

如果 MCU 有多个 I2C 外设，可以直接分到不同 bus：

```text
I2C1 -> 设备 A，地址 0x40
I2C2 -> 设备 B，地址 0x40
I2C3 -> 设备 C，地址 0x40
```

优点：

- 软件逻辑直观。
- 地址完全隔离。
- 电容也天然分段。

缺点：

- 占用更多 MCU 引脚。
- MCU I2C 外设数量有限。

#### 方案 4：电源/复位/使能隔离

如果设备支持 `EN`、`RESET` 或电源可控，可以每次只让一个设备在线：

```text
访问设备 A：打开 A，关闭 B/C
访问设备 B：打开 B，关闭 A/C
```

优点：

- 不一定需要专用 I2C mux。
- 适合低成本或已有电源控制的系统。

缺点：

- 切换慢。
- 设备每次上电/复位后可能要重新初始化。
- 不适合需要多个设备同时在线持续采样的场景。

### 9.3 面试回答模板

> 如果 I2C 模块地址固定且相同，不能直接挂在同一条总线上，因为它们会同时 ACK 和响应。常见解决方法是用 I2C 多路复用器，把相同地址设备放到不同通道；或者用 I2C 地址转换器，把其中一些设备映射成不同地址；也可以用多个 I2C 控制器、GPIO 模拟多路 I2C，或者通过电源/复位/使能脚保证同一时间只有一个设备在线。

## 10. 拔高题 4：如果就是想在一个 I2C 上挂载更多设备，怎么做？

### 10.1 先判断瓶颈是什么

想挂更多设备时，先判断当前受限于哪类问题：

| 瓶颈 | 现象 | 解决方向 |
| --- | --- | --- |
| 地址不够或地址冲突 | 扫描地址重复，多个设备同地址 | mux、地址转换器、多 I2C |
| 总线电容过大 | 上升沿慢，400k 不稳定 | 降速、减电容、buffer、mux |
| 上拉不合适 | 波形高电平慢或低电平拉不下去 | 重新计算 Rp |
| 线太长/干扰大 | 偶发 NACK、数据错、总线卡死 | 缩短线、降速、屏蔽、差分扩展 |
| 带宽不够 | 轮询周期过长 | 降低采样率、分 bus、换 SPI |
| 软件复杂度高 | 设备初始化/恢复混乱 | 分层驱动、总线管理器、超时重试 |

### 10.2 答案一：使用 I2C buffer/repeater/hub 分段

如果瓶颈是总线电容，可以用 I2C buffer 或 repeater 把总线分成多个电气段。

基本思路：

```text
MCU I2C 段
  ↓
I2C Buffer/Repeater
  ↓
下游 I2C 段
```

这样每一段只承受本段电容，不是所有设备电容简单堆到 MCU 那一侧。

优点：

- 增加可挂载设备数量。
- 改善上升时间。
- 支持更长走线或线缆。
- 某些 buffer 支持热插拔、电平转换、总线隔离。

注意：

- buffer 不是无限叠加魔法，传播延迟、方向判断、低电平门限都要看数据手册。
- 上下游每段仍然要分别计算上拉电阻和电容。
- 如果地址冲突，单纯 buffer 解决不了，需要 mux 或地址转换。

面试回答：

> 如果只是电容太大，可以用 I2C buffer/repeater 把总线分段，让每段满足电容和上升时间要求。每段单独配置上拉电阻，必要时降低速率或使用支持更大电流的 Fast-mode Plus 器件。

### 10.3 答案二：使用 I2C 多路复用器

I2C 多路复用器是另一个很常见答案，例如 1 路主 I2C 扩展到 4 路或 8 路下游 I2C。

基本结构：

```text
MCU I2C
  ↓
I2C MUX
  ├── Bus 0: 设备 0..n
  ├── Bus 1: 设备 0..n
  ├── Bus 2: 设备 0..n
  └── Bus 3: 设备 0..n
```

优点：

- 可以隔离电容。
- 可以解决相同地址设备冲突。
- 下游某一路异常时，系统可以尝试切走该通道。
- 扩展方式直观。

缺点：

- 每次访问前要先选择通道。
- 增加器件成本和软件状态。
- 多个通道同时打开时要重新考虑地址冲突和电容叠加。

面试回答：

> 如果想在一个 I2C 主控上挂更多设备，可以用 I2C 多路复用器，把一个主总线拆成多个下游通道。这样主机仍然只有一组 I2C，但每次选择一个通道访问。它既能减少单段电容，也能处理多个相同地址设备。

### 10.4 其他可补充方案

- 降低 I2C 速率，例如从 400k 降到 100k，提高时序裕量。
- 重新选择上拉电阻，保证 `Rp(min) <= Rp <= Rp(max)`。
- 缩短走线，减少连接器和线缆电容。
- 减少高电容 ESD/TVS 器件。
- 使用多个 MCU I2C 外设分摊设备。
- 对长距离通信，考虑差分 I2C extender，或直接改用 CAN、RS-485、UART 等更适合长线的方案。
- 如果数据量大，不要勉强堆 I2C，考虑 SPI 或并行/高速接口。

## 11. 适合追问的工程题

### 11.1 I2C 扫描能扫到地址，是否说明设备一定正常？

不一定。

扫描通常只是发送地址，看有没有 ACK。它只能说明该地址上有设备响应，不能说明：

- 设备寄存器读写正常。
- 设备配置正确。
- 数据有效。
- 波形在目标速率下稳定。
- 没有地址冲突。

更可靠的检查：

- 读取固定 ID 寄存器。
- 写寄存器后读回确认。
- 检查数据 ready/status 位。
- 对关键数据做 CRC 或范围校验。
- 用逻辑分析仪看 ACK、重复起始、时钟和数据边沿。

### 11.2 I2C 为什么不适合长线？

因为 I2C 是开漏上拉结构，线越长：

- 电容越大。
- 上升沿越慢。
- 对干扰越敏感。
- 地电位差和串扰问题更明显。

如果一定要长线：

- 降低速率。
- 减小上拉电阻但不超过器件下拉能力。
- 使用屏蔽线、双绞线、良好地参考。
- 使用 I2C buffer/extender。
- 距离更长时考虑 RS-485、CAN 等差分总线。

### 11.3 SPI 为什么通常比 I2C 快？

主要原因：

- SPI 通常是推挽输出，上升/下降沿更快。
- SPI 数据线分开，MOSI/MISO 可全双工。
- SPI 没有地址、ACK、仲裁等固定开销。
- SPI 协议简单，时钟可以跑到更高。

但 SPI 也不是越快越好：

- 线长会限制速率。
- 多从机挂载会增加负载。
- SCLK 边沿过快会带来反射、串扰、过冲。
- 不同设备最大 SPI clock 不同。

### 11.4 SPI MISO 为什么会冲突？

多个从机的 MISO 连接到同一根线上。如果未选中的从机没有高阻，而是仍然输出高/低电平，就会和被选中的从机同时驱动 MISO。

后果：

- 主机读到错误数据。
- 两个芯片输出相反电平时可能产生较大电流。
- 波形畸变。

解决：

- 确认从机数据手册：CS 无效时 MISO 是否高阻。
- 每次只拉低一个 CS。
- 必要时给 MISO 加三态缓冲器。
- 对异常器件做单独 MISO 或隔离。

### 11.5 SPI 和 I2C 谁更可靠？

不能简单说谁更可靠，要看场景。

I2C：

- 有 ACK，能知道地址/字节级别是否有响应。
- 但开漏上拉导致速度和抗干扰能力受电容影响大。
- 地址冲突、总线卡死是常见问题。

SPI：

- 推挽高速，时序简单。
- 但没有标准 ACK，读写是否成功要靠器件状态和上层校验。
- 多从机时要小心 CS、MISO 高阻和 mode 切换。

面试回答：

> I2C 在协议层有 ACK 和仲裁，但电气上更受上拉和电容影响；SPI 电气和时序更直接，速度高，但协议层缺少统一确认机制。可靠性最终取决于硬件设计、时序裕量、错误处理和上层校验。

### 实战问题

最后就是主播遇到的一些真实场景和真实的面试题

要怎么设计，用什么方案？

一方面可以规避之前的总线电容上限，另外也可以扩大总挂载器件

另外就是用地址转换器，相对来说硬件设计复杂一点，但软件设计更简单

因为针对主机来说，就像是在使用不同地址的IIC设备一样

每一个时间段只给一个设备上电

但这种方法针对需要预热的设备或者高频数据采样不友好

另外针对SPI，我们都知道一般是由Master发起数据传输

但是如果有一个需求是Slave要发起数据传输，要怎么设计？

一个常见的方法是需要增加一根GPIO中断/握手线

用来让从机通过这跟线来通知主机去申请让主机选中自己并传输数据
