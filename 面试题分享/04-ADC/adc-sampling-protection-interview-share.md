# ADC 采样与硬件保护嵌入式面试分享题库

> 适用场景：嵌入式软件、MCU 驱动、电机控制、数字电源、储能 BMS、工业采集与功率变换器方向面试。
>
> 说明：ADC 面试很少停在“启动转换并读取数值”。常见追问会继续进入采样时间、参考电压、源阻抗、定时器触发、DMA、多通道同步、PWM 采样窗口、校准、Analog Watchdog 和硬件保护链。

### 2.4 第一等级：基础知识详细答案

#### 2.4.1 ADC 的一次转换经历哪些过程？

MCU 中常见的 SAR ADC 会先把输入电压接到内部采样保持电容。采样时间结束后，开关断开，ADC 用逐次逼近的方法把保持电压和内部 DAC 输出比较，逐位确定数字结果。

一次转换至少包含：

1. 输入信号建立。
2. 采样电容充电。
3. 采样保持。
4. 逐次逼近或其他量化过程。
5. 结果写入数据寄存器，并按配置产生中断或 DMA 请求。

面试回答：

> ADC 不是瞬间读取引脚电压。它先在采样阶段给内部采样电容充电，再在转换阶段完成量化。采样时间过短时，后面的数字结果即使稳定，也可能稳定在错误值上。

#### 2.4.2 12 位 ADC 的分辨率怎样计算？

12 位 ADC 有 `2^12 = 4096` 个量化等级，输出码通常从 0 到 4095。

理想 LSB 大小：

```text
LSB = VREF / 4096
```

若 `VREF = 3.3 V`：

```text
LSB = 3.3 / 4096 ≈ 0.806 mV
```

把满量程端点映射到最大码值时，也常见下面的换算：

```text
Vin ≈ Code * VREF / 4095
```

工程中要说明采用哪一种定义，不要把“量化步长”和“满量程端点换算”混为一谈。

#### 2.4.3 分辨率高是否等于精度高？

分辨率描述 ADC 能把满量程分成多少档；精度还受到很多误差影响：

- 参考电压误差和噪声。
- ADC offset 与 gain error。
- INL、DNL 和有效位数 ENOB。
- 输入前端运放误差。
- 电阻分压比误差。
- PCB 接地、串扰和温漂。

一个 12 位 ADC 可以输出 4096 个码值，但受噪声和非理想误差影响，有效位数通常低于标称位数。具体能达到多少，需要结合芯片指标和整条采样链实测。

#### 2.4.4 采样时间、转换时间和总转换时间怎么理解？

采样时间用于给内部采样电容充电；转换时间用于把保持电压量化成数字码。两者通常都以 ADC 时钟周期表示。

```text
T_total = T_sample + T_convert
```

以某款 12 位 ADC 为例，如果采样需要 19.5 个 ADC 周期，转换需要 12.5 个周期：

```text
总周期 = 19.5 + 12.5 = 32 cycles
最大理论转换率 = f_adc / 32
```

具体转换周期必须查对应芯片参考手册，不同分辨率和工作模式可能不同。

#### 2.4.5 为什么信号源阻抗大会导致采样偏低或不稳定？

外部信号源的等效电阻与 ADC 内部采样电容形成 RC 网络。采样开关闭合后，电容需要一定时间充到接近真实输入电压。源阻抗越大，建立时间越长。

常见改进：

- 延长 ADC sampling time。
- 降低分压网络阻值。
- 在 ADC 前增加合适的驱动运放。
- 合理设置输入端 RC，并重新检查建立时间。
- 多通道切换时丢弃第一次结果，前提是芯片和项目确有该需要。

#### 2.4.6 参考电压为什么重要？

ADC 测到的实质是 `Vin / VREF`。参考电压变化 1%，理想换算结果也会产生约 1% 的比例误差。

工程上要检查：

- VREF 来自 VDDA 还是独立基准源。
- 参考电压的容差、温漂和噪声。
- VDDA/VREF 的去耦和 PCB 回流路径。
- 是否能读取内部参考通道，用来估算实际 VDDA。
- 软件换算是否仍然写死为 3.3 V。

### 2.5 第二等级：驱动应用详细答案

#### 2.5.1 轮询、中断和 DMA 怎么选？

| 方式 | 适合场景 | 主要限制 |
| --- | --- | --- |
| 轮询 | 上电自检、低频单次采样、简单调试 | CPU 等待转换完成 |
| 中断 | 低到中等采样率、转换完成后需要立即处理 | 采样频率高时中断负载大 |
| DMA | 多通道、连续采样、高采样率、波形缓存 | 要处理缓冲区、Cache 和数据同步 |

面试回答：

> 少量低频数据可以轮询；需要异步处理时使用中断；多通道连续数据更适合定时器触发 ADC，再由 DMA 搬到内存。DMA 只负责搬运，采样时刻和缓冲区处理仍要单独设计。

#### 2.5.2 多通道扫描加 DMA 时要注意什么？

ADC 按配置的 rank 顺序转换各通道，DMA 再按转换完成顺序写入内存。需要同时确认：

- 通道序列和 rank 是否正确。
- DMA memory/peripheral data width 是否与 ADC 数据寄存器匹配。
- DMA buffer 长度是否等于“通道数 × 每批组数”。
- Circular 模式下半传输和全传输回调处理哪一半数据。
- 处理任务是否能在下一次覆盖前消费完数据。
- 多通道源阻抗差异是否需要不同采样时间。

#### 2.5.3 为什么更推荐定时器触发 ADC？

自由连续转换的采样间隔受 ADC 自身转换链控制，采样时刻也很难与 PWM、控制周期或外部事件建立固定关系。

定时器触发可以获得：

- 固定采样周期。
- 更低的采样抖动。
- 与 PWM compare/update 事件同步。
- 可预测的 DMA 数据批次。
- 控制算法中稳定的离散时间间隔。

对低速温度采集，连续转换未必有问题；对电流环和波形分析，固定硬件触发通常更合适。

#### 2.5.4 ADC 数值一直跳应该怎么排查？

建议按采样链从前往后排查：

1. 用示波器测 ADC 引脚，确认模拟信号本身是否稳定。
2. 检查 VREF/VDDA、模拟地和去耦。
3. 检查信号是否超出 ADC 输入范围。
4. 检查源阻抗、采样时间和通道切换影响。
5. 检查 PWM、DC-DC、数字 IO 是否在采样点附近切换。
6. 固定单通道采样，排除扫描序列和 DMA 错位。
7. 检查数据宽度、对齐、Cache 和缓冲区越界。
8. 最后再考虑平均、低通或异常值处理。

滤波不能代替硬件和时序排查，否则可能只是把错误结果变得更平滑。

#### 2.5.5 Analog Watchdog 能代替硬件比较器吗？

Analog Watchdog 会在 ADC 转换完成后，把结果与上限、下限比较，越界时产生标志或中断。它适合监控母线电压、温度、电流慢速越限，也适合做软件保护的提前通知。

它仍然需要等待：

```text
触发 ADC
    ↓
完成采样和转换
    ↓
数字结果越限
    ↓
产生中断并执行软件
```

严重短路时，这条链路往往不够快。比较器直接连接驱动芯片失能或定时器 Break，才适合承担快速关断。

#### 2.5.6 过采样和平均能提高多少效果？

对近似独立的随机噪声，理论上每增加 1 位有效分辨率，通常需要约 4 倍采样数：

```text
增加 N 位，样本数约为 4^N
```

例如希望理论上增加 2 位，需要约 16 次采样再累加、缩放。它会降低输出更新率，也无法消除参考电压偏差、增益误差、固定串扰和饱和失真。

### 2.6 第三等级：项目实战详细答案

#### 2.6.1 电流采样为什么要和 PWM 同步？

MOSFET 或 IGBT 开关边沿附近常有电压跳变、地弹、反向恢复和运放恢复过程。随机采样可能在不同 PWM 相位拿到完全不同的噪声和电流状态。

常见方案：

```text
中心对齐 PWM
    ↓
定时器 compare/update 事件
    ↓
在有效导通区中部触发 ADC
    ↓
ADC 完成后运行电流环
    ↓
下一次 PWM 更新点统一加载占空比
```

“PWM 中点采样”是一种常见描述，真正项目还要结合单电阻、双电阻、三电阻拓扑以及最小导通时间判断有效窗口。

#### 2.6.2 电流零偏和比例系数怎样校准？

电流采样换算通常包含：

```text
I = (Code - OffsetCode) * VREF / (2^N) / (Rshunt * Gain)
```

其中 `N` 是 ADC 位数。启动校准时要确保功率级没有实际电流，在多个采样点上求平均得到 `OffsetCode`。量产或高精度项目还可以用已知电流校准增益，并根据温度修正零偏。

校准值需要检查范围，不能把接线错误、运放饱和或硬件损坏当成新的正常偏置保存下来。

#### 2.6.3 ADC 前端 RC 滤波器怎么选？

RC 滤波能压制高频开关噪声，也会带来响应延迟，并增加 ADC 采样建立时间。设计时要同时考虑：

- 被测信号带宽。
- PWM 开关频率。
- ADC 采样频率。
- 允许的相位延迟。
- ADC 推荐源阻抗。
- 运放驱动电容负载的稳定性。

截止频率不能只按“越低越干净”选择。电流环需要的有效带宽必须保留，采样点附近的瞬态也要靠同步时序处理。

#### 2.6.4 快速过流保护链应该怎么设计？

典型链路可以分成三层：

```text
电流采样电阻 / 霍尔传感器
    ↓
高速比较器或驱动芯片内部比较器
    ↓
驱动芯片 EN/FAULT + 定时器 Break/Trip
    ↓
硬件立即关闭 PWM

同时：故障信号 -> MCU 外部中断或 Break 中断 -> 软件锁存现场
```

快速关断不依赖 CPU。软件负责识别故障、保存快照、禁止危险重启和执行后续恢复策略。

#### 2.6.5 软件怎样保存第一故障现场？

故障中断里只保存最必要的信息：

- 首次故障类型和硬件标志。
- 时间戳或控制周期计数。
- 母线电压、相电流和温度快照。
- PWM 占空比、状态机状态和运行模式。
- 驱动使能与关键 GPIO 状态。

快照要设置“首次故障已锁存”标志，避免后续欠压、通信中断等连锁故障覆盖起始原因。SPI 读取驱动芯片详细寄存器、日志写入和故障上报应交给高优先级任务处理。

#### 2.6.6 多速率采样任务怎么安排？

不同信号不需要相同采样率：

| 信号 | 常见处理思路 |
| --- | --- |
| 相电流、电感电流 | 与 PWM 同步，每个控制周期采样 |
| 母线电压 | 中速采样，可与控制周期分频 |
| 电池单体电压 | 根据 AFE 转换周期和均衡策略安排 |
| 温度 | 低速采样并滤波 |
| 绝缘、辅助电源 | 按诊断周期采样 |

可以用一个高速硬件触发序列承担控制采样，再由计数分频、独立 ADC 序列或任务周期处理慢变量，避免所有通道都占用最高采样率。

### 2.7 常见计算题模板

#### 2.7.1 ADC 码值换算输入电压

条件：12 位 ADC，`VREF = 3.3 V`，采样值 `Code = 2482`。

```text
Vin ≈ 2482 * 3.3 / 4095
Vin ≈ 2.000 V
```

若前端是 `30kΩ : 10kΩ` 分压：

```text
Vsource = Vin * (30k + 10k) / 10k
Vsource ≈ 8.00 V
```

#### 2.7.2 电流采样换算

条件：12 位 ADC，`VREF = 3.3 V`，零偏 `2048`，当前码值 `2296`，采样电阻 `5 mΩ`，运放增益 `20`。

```text
Vsense = (2296 - 2048) * 3.3 / 4096
Vsense ≈ 0.1998 V

I = Vsense / (0.005 * 20)
I ≈ 2.00 A
```

#### 2.7.3 单 ADC 最大理论转换率

条件：ADC 时钟 `40 MHz`，采样时间 `19.5 cycles`，12 位转换时间 `12.5 cycles`。

```text
总周期 = 19.5 + 12.5 = 32 cycles
最大理论转换率 = 40 MHz / 32
                 = 1.25 MSPS
```

如果每次触发扫描 5 个通道，忽略额外开销：

```text
最大序列频率 ≈ 1.25 MSPS / 5
             ≈ 250 kHz
```

第一个高频问题

12 位 ADC 到底是什么意思

12 位 ADC 一共有 2 的 12 次方

也就是 4096 个量化等级

如果参考电压是 3.3V

那么一个 LSB 大约就是 3.3V 除以 4096

也就是 0.8mV 左右

采样值再乘上这个分辨率

就可以得到 ADC 引脚上的电压

但是这里一定要注意

这个电压只是 MCU 引脚上的电压

如果前面还有分压电阻

采样电阻

或者运放增益

最后还要把这些比例关系反算回去

比如做电机相电流采样

一般还会给信号加一个中点偏置

所以软件启动的时候

最好先做一次零电流偏置校准

否则后面的电流环一开始就带着误差

第二个高频问题

就是采样时间和转换时间有什么区别

采样时间是 ADC 内部采样电容

连接到外部信号并充电的时间

转换时间是 ADC 把这个电压

真正量化成数字结果的时间

如果外部信号源阻抗比较大

采样时间又配得特别短

内部采样电容还没有充到真实电压

ADC 就开始转换了

最后读出来的数值自然不准

所以 ADC 不是采样时间越短越好

要结合信号源阻抗

ADC 时钟

目标采样频率

以及芯片手册一起计算

### 第二等级：驱动应用与保护题

进一步的，就是一些实际项目中的问题

比方说

多个 ADC 通道怎么连续采样

比较常见的方案就是

用定时器产生固定的触发事件

ADC 开启扫描模式

再用 DMA 把转换结果自动搬到内存

如果是连续数据流

DMA 可以使用 Circular 模式

这样 CPU 不需要每个通道都进一次中断

只需要在 DMA 半满或者全满的时候

批量处理这一组数据

这时候还有一个问题

电机电流或者变换器电感电流

不能随便找一个时间采

因为 PWM 开关边沿附近噪声非常大

所以更常见的做法是

让 PWM 定时器在周期中间

或者指定的 Compare 位置触发 ADC

这样每次采样时刻都是固定的

采样值也会稳定很多

第二个问题

就是硬件保护和软件保护如何配合

比如出现短路或者严重过流

千万不要等软件任务慢慢读取 ADC

再判断是否需要关闭 PWM

因为功率管可能在软件反应之前

就已经损坏了

更可靠的方案是

用外部比较器

首先用运放做硬件保护

例如一旦电流超过阈值了

给出一个带自锁过流信号

到驱动芯片的失能引脚

先把驱动芯片锁住，这一般是ns级别的，

进一步的，把这个信号同步给到软件

例如高级定时器的 Break 输入

一旦发生过流

定时器也能立刻关闭 PWM

这条保护链路不需要 CPU 参与

速度也是最快的

但是硬件把 PWM 关掉以后

软件还需要第一时间知道

到底发生了什么故障

最快的软件方式不是任务轮询

而是直接使用中断

如果故障已经接入定时器 Break

就开启 Break interrupt

中断触发以后

软件立即读取定时器的 Break 标志

以及当前关键的 ADC 采样值

然后把故障类型

发生时间

母线电压和电流快照

锁存到一个 fault snap 里面

这样就不会被后面产生的连锁故障覆盖

如果保护阈值本身来自 ADC

还可以使用 ADC 的 Analog Watchdog

提前配置上限和下限

ADC 每次转换完成后由硬件比较

一旦超出窗口就直接产生中断

肯定比任务里面不断轮询更快

但是大家要注意

Analog Watchdog 仍然需要等待 ADC 完成转换

所以短路这种微秒级故障

还是应该交给比较器和 Break 硬件保护

另外故障中断里面也不要 printf

不要 Delay

也不要阻塞读取一大串 SPI 寄存器

中断里只负责锁存现场

关闭其他危险输出

然后通知一个高优先级任务

让任务再去读取驱动芯片的详细故障寄存器

记录日志

最后由业务层决定是锁死

降额运行

还是延时以后重新启动

这个链路是许多电力电子项目用到的方案

每一步怎么做以及目的是什么都能回答清楚的话
